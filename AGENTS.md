# AGENTS.md

Guidance for AI coding agents working in this repository. Read this before making changes.

## Project Overview

**Estimator Web Application** (`estatimator-webapp`) is a monorepo containing two independently-run subprojects:

| Layer | Path | Stack |
|-------|------|-------|
| Backend (Python) | `./api_services` | Python ≥3.14, FastAPI, SQLModel + SQLAlchemy 2.0 (sync), Alembic, PostgreSQL (`psycopg`), managed with `uv`, formatted/linted with `ruff` |
| Frontend (TypeScript) | `./web_app` | React 19, Vite via `vite-plus` (`vp`), TanStack Router (file-based) + TanStack Query, Tailwind CSS v4, `orval` client generation, package manager `pnpm` |

The backend owns the API contract. On startup it writes an OpenAPI spec (`api_services/openapi/spec.json`), and the frontend generates its typed API client from that spec via `orval`. **Treat the backend OpenAPI spec as the single source of truth for API types.**

## Backend — `api_services`

### Setup & run

Run all commands from `api_services/`.

```sh
uv sync                     # install/update deps
uv run uvicorn api_services.main:app --reload \
  --reload-exclude "openapi.json" --reload-exclude "openapi.json.sha256"
```

- Copy `.env.example` → `.env` and fill in `DATABASE_URL` (must be `postgresql://…` or `postgresql+psycopg://…`) and `JWT_SECRET_KEY` (≥64 hex chars).
- The ASGI import path is **`api_services.main:app`** (package layout is `src/api_services/`). The root `api_services/README.md` still shows `app.main:app`, which is stale — there is no `app` package.

### Lint & format

```sh
uv run ruff check .          # lint
uv run ruff check . --fix    # autofix
uv run ruff format .         # format
```

Ruff config lives in `pyproject.toml` (`src = ["src"]`, first-party package `api_services`). Alembic also runs `ruff format` as a post-write hook.

### Database migrations (Alembic)

`alembic/env.py` imports `api_services.models` and uses `api_services.core.database.database_engine` + `api_services.models.target_metadata`. To pick up a new model in autogenerate, you **must** add its import to `src/api_services/models.py`.

```sh
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
uv run alembic downgrade -1
```

### Architecture & conventions

- **Feature-oriented structure**: each domain lives in `src/api_services/features/<feature>/` with the same file roles:
  - `models.py` — SQLModel tables + request/response schemas
  - `service.py` — business logic operating on a `Session`
  - `router.py` — FastAPI `APIRouter` endpoints
  - `deps.py` — FastAPI dependencies (auth, current user, etc.)
- **Routers** are registered in `main.py` with an explicit `prefix` (e.g. `app.include_router(auth_router, prefix="/auth")`) and a `tags=[...]` on the `APIRouter`.
- **Models**: SQLModel-first. Use the shared mixins from `core/models.py`:
  - `IdMixin` → UUID primary key (`uuid4`)
  - `TimestampMixin` → `created_at` / `updated_at` (UTC)
  - `SoftDeleteMixin` → `deleted_at` (nullable, indexed)
  - Prefer soft deletes (`deleted_at == None` filters) over hard deletes.
  - Use `TYPE_CHECKING` imports to avoid circular imports between `users`/`admin` and `auth`/`admin_auth` models.
- **Database is synchronous**: `core/database.py` uses `create_engine` + `sqlmodel.Session`, and injects it via `DatabaseSession = Annotated[Session, Depends(...)]`. Do **not** introduce `AsyncSession`/async engine without coordinating — it would break Alembic and existing services.
- **Pydantic schemas** (request/response bodies) live alongside the models; base "table-less" models are plain `SQLModel` classes, table models set `table=True`.
- **Security** (`core/security.py`): argon2 for password/OTP hashing, PyJWT for ephemeral tokens and short verification flows, opaque random `secrets.token_urlsafe` session tokens stored in httpOnly, `secure`, `samesite="lax"` cookies. Do not leak secrets to logs.
- **Settings** (`core/settings.py`): add new env vars to `AppSettings` **and** `.env.example`, and note that new vars must also be provisioned in the deployed environment.

## Frontend — `web_app`

### Setup & run

Run all commands from `web_app/`. The toolchain is **`vp`** (vite-plus), not raw `vite`.

```sh
vp install               # install deps (pnpm under the hood)
vp dev                   # dev server (router plugin regenerates routeTree.gen.ts on the fly)
vp build                 # production build
vp preview               # preview build
vp run generate-routes   # package.json script → `tsr generate` (manual routeTree regen)
vp exec orval            # regenerate src/api/* from the backend OpenAPI spec (no npm script exists)
```

> If `tsr` / `orval` report "not found in node_modules/.bin", the dependency install is incomplete — re-run `vp install`. `vp dlx <package>` can execute a package binary without installing it as a dependency.

### Format & lint

Formatting and linting are configured inside `vite.config.ts` (`fmt` and `lint` blocks) and executed by `oxfmt`/`oxlint` (the OXC toolchain), not Prettier/ESLint:

```sh
vp fmt           # format
vp fmt --check   # verify formatting
vp lint          # lint
vp check         # combined format + lint + type check
```

Key formatting rules (from `vite.config.ts`): `printWidth: 120`, single quotes (including JSX), trailing commas, sorted imports.

### Architecture & conventions

- **File-based routing** (TanStack Router). Add routes as files under `src/routes/`; `src/routeTree.gen.ts` is generated by the router plugin — never edit it.
- **Path aliases**: `#/*` and `@/*` both map to `./src/*`. Prefer these over deep relative imports.
- **Data fetching**: TanStack Query. Follow the `router-query-integration` skill — define `queryOptions` helpers, prefetch in route loaders with `queryClient.ensureQueryData(...)`, then consume with `useQuery`/`useSuspenseQuery`.
- **TypeScript is strict**: `strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax` are enabled. Type-only imports must use `import type`.
- **Styling**: Tailwind CSS v4 (via `@tailwindcss/vite`); global styles in `src/styles.css`.
- **Package manager**: `pnpm` (see `pnpm-lock.yaml` / `pnpm-workspace.yaml`), invoked through `vp`.

### Generated code — do not edit by hand

- `src/routeTree.gen.ts` — generated by `@tanstack/router-plugin` (also marked read-only in `.vscode/settings.json`)
- `src/api/*.ts` and `src/api/*.zod.ts` — generated by `orval` from the backend OpenAPI spec

If a generated API type or endpoint is wrong, change the backend and regenerate — do not patch the generated files.

## API Contract Workflow

The two subprojects are coupled only through the OpenAPI spec:

1. Backend starts → `lifespan.py` serializes `app.openapi()` to `api_services/openapi/spec.json` and writes a sha256 hash (`spec.json.sha256`). It only rewrites when the hash changes.
2. `web_app/orval.config.ts` reads `../api_services/openapi/spec.json` and generates:
   - a React Query + axios client into `src/api/`
   - Zod schemas (`*.zod.ts`) using Zod v4 mini
3. Regenerate the frontend client after any backend API change, then commit the updated generated files.

When adding an endpoint, use clear FastAPI `tags` and `response_model`s — orval groups output by tag and derives TypeScript types from the Pydantic schemas.

## General Conventions

- Keep changes scoped to the relevant subproject; don't mix backend and frontend concerns in one change unless the API contract is shifting.
- Match existing naming: Python `snake_case` (SQLModel fields, functions), TypeScript `camelCase` for values / `PascalCase` for components and types.
- Run the relevant formatter/linter before finishing:
  - Backend: `uv run ruff check . && uv run ruff format .`
  - Frontend: `vp check`
- Regenerate and commit derived artifacts when inputs change: Alembic migrations, `openapi/spec.json` (+ hash), `routeTree.gen.ts`, and `src/api/*`.
- Do not commit secrets. `.env` holds real credentials; `.env.example` documents the expected variables.
- Prefer ASCII/UTF-8 text; keep files free of `__pycache__`/build output (already gitignored).
